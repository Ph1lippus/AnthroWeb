NOTES — WORK & FUNCTIONALITY AUDIT
==================================
Generated from investigation of src/Components/Notes/* and src/utils/note*.

------------------------------------------------------------
1. DRAG HANDLE (block grip) — src/Components/Notes/NoteEditor.tsx
------------------------------------------------------------
- [FIXED] Handle was vertically centered across the whole block instead of the
  first line. Root cause: @tiptap/extension-drag-handle positions against a
  virtual element, so state.elements.reference had no getComputedStyle. Fixed by
  tracking the real block DOM node in handleElementRef (updated in onNodeChange)
  and reading lineHeight/fontSize from it.
- [TUNE] Horizontal gutter offset changed -14 -> -20 and vertical nudge -2px
  for a bit more breathing room. May need further tuning per block type.
- [OPEN] Nested blocks (list items) use a different reference element in the
  plugin's update() path (getOuterDomNode) than in mousemove; handleElementRef
  can be stale there, causing slight misalignment after doc changes while the
  handle is visible.
- [OPEN] Handle is hidden on mobile (CSS 7583); no alternative affordance
  beyond the header button, which only opens against the caret's block.

------------------------------------------------------------
2. TO-DO / TASK LIST SPACING — src/utils/noteEditorExtensions.ts, src/index.css
------------------------------------------------------------
- [ROOT CAUSE] TaskItem content is `paragraph+` (or `paragraph block*` when
  nested), so a single to-do can accumulate several paragraphs. Enter then
  Backspace/Delete leaves a stray empty paragraph inside the item, adding a
  blank line and making that row taller than its neighbours ("nested above and
  below but not together").
- [CONFIG MISMATCH] Comment said "deliberately not nested: true" but code set
  `nested: true`. Changed to false, but this alone does not stop stray empty
  paragraphs (content is still paragraph+).
- [RISK] My attempt to force `content: 'paragraph'` (single) broke
  toggleTaskList / Enter (schema errors on zero-paragraph items). REVERT and
  keep `paragraph+`; clean up stray empties at runtime instead.
- [CSS] `.note-prose ul[data-type='taskList']` forced to flex column caused
  layout side effects. Revert to block display; keep spacing via li margins +
  adjacent-list margin collapse.
- [OPEN] Adjacent task lists (item lifted out of a list) render as separate
  <ul> with doubled margins. Fix: `.taskList + .taskList { margin-top: 0 }`.
- [OPEN] Empty paragraph collapse safeguard
  (`p:has(> br:only-child):not(:only-child) { display: none }`) depends on
  :has support and ProseMirror's <p><br></p> rendering; verify in target
  browsers.
- [OPEN] Load-time normalizer re-serialized the whole document via DOMParser,
  risking HTML changes. Move cleanup to a runtime appendTransaction plugin and
  drop the broad normalizer.

------------------------------------------------------------
3. LIST / BLOCK BEHAVIOUR
------------------------------------------------------------
- ExitEmptyListItem (Enter on blank item exits list) handles single-item and
  multi-item cases; verify it still works with nested:false.
- Tab no longer nests todos (intended trade-off); documented but may surprise.
- Bulleted/ordered lists share paragraph+ content; same stray-empty-paragraph
  issue may apply, though less reported.
- Move up/down on first/last item inside a toggle lifts out (intended).
- Delete on last line inside a toggle removes the whole toggle (intended).

------------------------------------------------------------
4. EDITOR CORE — src/Components/Notes/NoteEditor.tsx
------------------------------------------------------------
- Uncontrolled editor; parent owns stored HTML, reconciled once on mount.
  Autosave debounce lives in parent (NoteEditorPane) — verify no lost updates
  on fast navigation/unmount.
- StrictMode double-mount: editor destroyed between mounts; code guards with
  isDestroyed. Check for leaked plugins/listeners.
- Block menu placement is hand-rolled (no floating-ui); scroll closes it.
  Selection-based menu cannot hold focus (keys forwarded via ProseMirror).
- Drag handle hidden on mobile; header button is the only entry there.
- Focus mode dims non-caret blocks via CSS has-focus; verify with nested
  blocks.
- TrailingNode is off; deleting last block handled by deleteBlocks, but other
  paths (e.g. Backspace) may leave an empty document.
